[[ext-fns-text]]
==== Text Functions

NOTE: The text functions read a string by Unicode character, as `size()` counts it, so a character outside the Basic Multilingual Plane (an emoji, a letter of Deseret or Adlam, a CJK Extension B ideograph) is one character: `text.capitalize()`, `text.decapitalize()`, `text.capitalizeAll()` and `text.decapitalizeAll()` map its case, `text.camelCase()`, `text.snakeCase()` and `text.upperCamelCase()` take a letter outside the plane for a letter and not for a word break, `text.replace()` and `text.split()` with an empty regular expression cut between characters and never inside one, and `text.random()` draws whole characters. The openCypher `ltrim()`, `rtrim()`, `btrim()` and `trim()` with a set of characters to strip do the same. _(Since v26.11.1, issues #10484 and #10485)_ Before, they worked on UTF-16 units and could return half of a character. The distance and similarity functions (`text.hammingDistance()`, `text.levenshteinDistance()`, `text.levenshteinSimilarity()`, `text.jaroWinklerDistance()` and `text.sorensenDiceSimilarity()`) compare characters too _(since v26.11.1, issue #10417)_: one emoji replaced by another is one edit, `text.hammingDistance()` compares the number of characters and not of UTF-16 units, the 10,000 character limit of `text.levenshteinDistance()` counts characters, and a bigram of `text.sorensenDiceSimilarity()` is never cut inside a character. The number for two strings is the one for the same two strings written with characters of the Basic Multilingual Plane.

[[text-camel-case]]
===== text.camelCase()

Convert a string to camelCase. The words are the runs of letters and digits, each one lower-cased and then capitalized, and the first character of the result is lower case. The blanks and separators around the words are dropped.

*Syntax:* `text.camelCase(string)`

*Returns:* String - camelCase string

*APOC Compatible:* `apoc.text.camelCase`

_(Since v26.12.1, issue #12104)_ A separator in front of the first word no longer capitalizes it: `'  padded  '` is `padded`, it was `Padded`.

[source,cypher]
----
RETURN text.camelCase("hello world") AS result
// Returns: "helloWorld"

RETURN text.camelCase("hello_world") AS result
// Returns: "helloWorld"

RETURN text.camelCase("  padded  ") AS result
// Returns: "padded"
----

[[text-format]]
===== text.format()

Format a string using printf-style formatting. The values are given as one list. Number formatting (`%f`, `%e`, `%d`, etc.) does not depend on the server's configured locale: it follows the `language` argument, `'en'` by default (`.` as decimal separator).

*Syntax:* `text.format(format, params, [language])`

*Parameters:*
[%header,cols="2,2,4"]
|===
| Parameter | Type | Description
| format | String | The format, as in Java `String.format()`
| params | List | The values for the format specifiers. A value that is not a list is the one value. When it is `null`, the format is returned as it is
| language | String | Optional - Language code that gives the decimal and grouping separators (default: `'en'`)
|===

*Returns:* String - Formatted string

*APOC Compatible:* `apoc.text.format`

_(Since v26.12.1, issue #12104)_ The values are one list, as in APOC: `text.format('%s-%d', ['a', 3])`. Before, they were the following arguments, and `text.format('%s %d', 'a', 1)` now reads `'a'` as the one value and `1` as the language. The separators of a number follow the language.

[source,cypher]
----
RETURN text.format("%s-%d", ["a", 3]) AS result
// Returns: "a-3"

RETURN text.format("%,d", [1234567], "de") AS result
// Returns: "1.234.567"
----

'''

[[text-jaro-winkler-distance]]
===== text.jaroWinklerDistance()

Calculate the Jaro-Winkler distance between two strings: 1 minus their Jaro-Winkler similarity. Returns a value between 0.0 (identical) and 1.0 (nothing in common). This metric is especially effective for detecting typos and misspellings because it gives extra weight to matching prefixes.

*Syntax:* `text.jaroWinklerDistance(string1, string2)`

*Returns:* Double - Distance (0.0 to 1.0), the smaller the more similar

*APOC Compatible:* `apoc.text.jaroWinklerDistance`

_(Since v26.12.1, issue #12104)_ The function answers the distance, as APOC does. Before, it answered the similarity (1.0 for equal strings), so a query that kept the names with `> 0.85` must now keep those with `< 0.15`, and one that sorted by `score DESC` must sort by `score ASC`.

[source,sql]
----
-- Find similar names using fuzzy matching
SELECT name, text.jaroWinklerDistance(name, 'John') AS score
  FROM Person
  WHERE text.jaroWinklerDistance(name, 'John') < 0.15
  ORDER BY score ASC

-- Compare two literal strings
SELECT text.jaroWinklerDistance('hello', 'helo') AS score
-- Returns: ~0.047
----

[source,cypher]
----
RETURN text.jaroWinklerDistance("hello", "helo") AS score
// Returns: ~0.047

MATCH (p:Person)
WHERE text.jaroWinklerDistance(p.name, "John") < 0.15
RETURN p.name, text.jaroWinklerDistance(p.name, "John") AS score
ORDER BY score ASC
----

'''

[[text-levenshtein-distance]]
===== text.levenshteinDistance()

Calculate the Levenshtein (edit) distance between two strings. Returns the minimum number of single-character edits (insertions, deletions, or substitutions) required to change one string into the other.

*Syntax:* `text.levenshteinDistance(string1, string2)`

*Returns:* Long - Number of edits required

NOTE: Each argument is limited to 10,000 characters. A longer string is rejected with `String length exceeds maximum
allowed`, because the computation cost grows with the two lengths multiplied together.

*APOC Compatible:* `apoc.text.levenshteinDistance`

[source,sql]
----
SELECT text.levenshteinDistance('kitten', 'sitting') AS distance
-- Returns: 3

SELECT name, text.levenshteinDistance(name, 'John') AS edits
  FROM Person
  WHERE text.levenshteinDistance(name, 'John') <= 2
----

[source,cypher]
----
RETURN text.levenshteinDistance("kitten", "sitting") AS distance
// Returns: 3
----

'''

[[text-replace]]
===== text.replace()

Replace every match of a regular expression. The replacement refers to the groups of the match as `$1` or `+${name}+`, and `+\$+` is a literal dollar sign.

*Syntax:* `text.replace(string, regex, replacement)`

*Returns:* String - String with replacements made, or `null` when an argument is `null`

*APOC Compatible:* `apoc.text.replace`

A pattern that is not valid, or a replacement that names a group the pattern does not have, is an error. The pattern is limited to 500 characters and runs under the `command.regexTimeout` deadline, as in `text.regexReplace()`.

_(Since v26.12.1, issue #12104)_ The second argument is a Java regular expression, as in APOC, where it was matched as literal text, and a `null` argument answers `null`. To replace literal text, escape the characters of the pattern that a regular expression reads (`"\\."` for a dot), or use the openCypher `replace()` function, which is literal.

[source,cypher]
----
RETURN text.replace("hello world", "world", "universe") AS result
// Returns: "hello universe"

RETURN text.replace("a1b22c", "[0-9]+", "#") AS result
// Returns: "a#b#c"

RETURN text.replace("hello", "(l+)", "<$1>") AS result
// Returns: "he<ll>o"
----

'''

[[text-snake-case]]
===== text.snakeCase()

Convert a string to snake case: lower-case words joined by `-`, as APOC does. A word starts at every character that is not a lower-case letter or an ASCII digit, so `"fooBarBaz"` is `foo-bar-baz`. A string made only of upper-case letters, digits and `_` (`"FOO_BAR"`) is first read as words separated by the underscores. The blanks around a word are dropped, and any other character stays at the start of its word (`"a.b"` is `a-.b`).

*Syntax:* `text.snakeCase(string)`

*Returns:* String - Snake case string

*APOC Compatible:* `apoc.text.snakeCase`

_(Since v26.12.1, issue #12104)_ The words are joined by `-`, where they were joined by `_`, and `"FOO_BAR"` is `foo-bar`, it was `f_o_o_b_a_r`.

[source,cypher]
----
RETURN text.snakeCase("helloWorld") AS result
// Returns: "hello-world"

RETURN text.snakeCase("FOO_BAR") AS result
// Returns: "foo-bar"
----

'''

[[text-sorensen-dice-similarity]]
===== text.sorensenDiceSimilarity()

Calculate the Sorensen-Dice similarity coefficient between two strings based on bigram (character pair) overlap. Returns a value between 0.0 (no common bigrams) and 1.0 (identical). Useful for comparing short strings and detecting near-duplicates.

*Syntax:* `text.sorensenDiceSimilarity(string1, string2, [languageTag])`

*Parameters:*
[%header,cols="2,2,4"]
|===
| Parameter | Type | Description
| string1, string2 | String | The strings to compare
| languageTag | String | Optional - IETF language tag the strings are upper-cased in (default: `'en'`). When it is `null`, the answer is `null`
|===

*Returns:* Double - Similarity score (0.0 to 1.0)

*APOC Compatible:* `apoc.text.sorensenDiceSimilarity`

_(Since v26.12.1, issue #12104)_ The strings are upper-cased, split into words at the blanks, and the bigrams of each word are compared as a multiset, as APOC does: a bigram never spans two words, and `'aa'` and `'aaaa'` share one of their four bigrams (0.5). Before, the bigrams were a case-insensitive set over the whole string (1.0 for `'aa'` and `'aaaa'`). A language tag changes the case mapping (`'İstanbul'` and `'istanbul'` are 1.0 with `'tr'`).

[source,sql]
----
SELECT text.sorensenDiceSimilarity('night', 'nacht') AS score
-- Returns: 0.25
----

[source,cypher]
----
RETURN text.sorensenDiceSimilarity("night", "nacht") AS score
// Returns: 0.25
----

'''

[[text-split]]
===== text.split()

Split a string around the matches of a regular expression.

*Syntax:* `text.split(string, regex, [limit])`

*Parameters:*
[%header,cols="2,2,4"]
|===
| Parameter | Type | Description
| string | String | The string to split
| regex | String | The Java regular expression that separates the pieces
| limit | Integer | Optional - With `0` (the default) the empty pieces at the end are dropped, with a negative number they are kept, and with a positive number the list has at most that many pieces, the last one holding the rest of the string
|===

*Returns:* List - List of substrings, or `null` when an argument is `null`

*APOC Compatible:* `apoc.text.split`

The result is the one of Java `String.split(regex, limit)`. The pattern has the limits of `text.replace()`.

_(Since v26.12.1, issue #12104)_ The second argument is a regular expression, as in APOC, where it was matched as literal text, and the empty pieces at the end are dropped unless `limit` is negative: `text.split("a,", ",")` is `["a"]`, and `text.split("a.b.c", ".")` is `[]` because `.` matches every character (write `"\\."` for a dot). The openCypher `split()` function and the SQL `.split()` method are not changed: they are literal and keep the empty pieces.

[source,cypher]
----
RETURN text.split("a,b,c", ",") AS parts
// Returns: ["a", "b", "c"]

RETURN text.split("a1b22c", "[0-9]+") AS parts
// Returns: ["a", "b", "c"]

RETURN text.split("a,b,,c,,", ",") AS parts
// Returns: ["a", "b", "", "c"]

RETURN text.split("a,b,,c,,", ",", -1) AS parts
// Returns: ["a", "b", "", "c", "", ""]

RETURN text.split("a,b,c", ",", 2) AS parts
// Returns: ["a", "b,c"]
----

'''
