[[sql-methods]]
==== Methods

SQL Methods are similar to <<sql-functions,SQL Functions>> but they apply to values.
In Object-Oriented paradigm they are called "methods", as functions related to a type.
So what's the difference between a function and a method?

This is a <<sql-functions,SQL Function>>:

[source,sql]
----
SELECT FROM sum( salary ) FROM employee
----

This is a SQL method:

[source,sql]
----
SELECT FROM salary.asJSON() FROM employee
----

As you can see the method is executed against a field/value.
Methods can receive parameters, like functions.
You can concatenate N operators in sequence.

WARNING: `<name>.<method>(...)` is read as a call of the namespaced function `<name>.<method>` when `<name>` is one of the function namespaces (`ts`, `geo`, `text`, `math`, `convert`, `date`, `util`, `coll`, `map`, `agg`, `node`, `rel`, `path`, `create`), even if `<name>` is a property of the record. Do not name properties like a namespace when you call methods on them (`date.asLong()` fails with `Unknown function name 'date.asLong'`); use another property name, such as `created`. Enclosing the name in backticks works for some of them (e.g. `date`), but not for all (`map` still fails).

NOTE: methods are case-insensitive.

===== Method Reference

[[methods-squares]]
====== []

Execute an expression against the item.
An item can be a multi-value object like a map, a list, an array or a document.
For documents and maps, the item must be a string.
For lists and arrays, the index is a number.

Syntax: `&lt;value&gt;[&lt;expression&gt;]`

Applies to the following types:

- document,
- map,
- list,
- array

*Examples*

Get the item with key "phone" in a map:

[source,sql]
----
SELECT FROM Profile WHERE '+39' IN contacts[phone].left(3)
----

Get the first 10 tags of posts:

[source,sql]
----
SELECT FROM tags[0...9] FROM Posts
----

[[append]]
====== append()

Appends one or more string to the result. A `null` argument is skipped, wherever it appears, and the remaining
arguments are still appended: `'x'.append(null, 'A', 'B')` returns `xAB`. A `null` receiver returns `null`.

Syntax: `&lt;value&gt;.append(&lt;value&gt;[,&lt;value&gt;]*)`

Applies to the following types:

- string

*Examples*
[source,sql]

----
SELECT name.append(' ').append(surname) FROM Employee
----

'''

[[asboolean]]
====== asBoolean()

Transforms the field into a Boolean type.
If the origin type is a string, then `"true"` (or `"TRUE"`, `"True"`, ...) means `TRUE`,
all other strings transform to `FALSE`.
If it is a number type, then `0` means `FALSE` while all other numbers transform to `TRUE`.
In case a `NULL` is passed then `NULL` is also returned.

Syntax: `&lt;value&gt;.asBoolean()`

Applies to the following types:

- string,
- short,
- int,
- long

*Examples*

[source,sql]
----
SELECT FROM Users WHERE online.asBoolean() = true
----

'''

[[ascypherrid]]
====== asCypherRID()

Converts a record or RID into the numeric (`Long`) form returned by the native OpenCypher `id()` function, so SQL queries can produce values that round-trip
with Cypher. The two components of an ArcadeDB RID (`bucketId`, `position`) are packed into a single non-negative number using 63 of the 64 bits (the sign bit is
kept clear). The split between bucketId and position is controlled by the global setting `arcadedb.opencypher.idBucketBits` (default `16`, see
<<arcadedb-settings,Settings>>); the same value must be used to encode and decode, and the method fails with an error if a component does not fit the reserved bits.

Syntax: `&lt;value&gt;.asCypherRID()`

Applies to the following types:

- record,
- RID,
- string (in the `#bucketId:position` form),
- number (returned unchanged)

*Examples*

[source,sql]
----
SELECT @rid.asCypherRID() AS ident FROM Person WHERE name = 'Alice'
----

To resolve a record back from a Cypher id, use the inverse <<cypherrid,`cypherRID()`>> function, e.g. `SELECT FROM cypherRID(:id)`.

'''

[[asstring]]
====== asString()

Transforms the field into a string type.

For numeric vectors (a `float[]`/`double[]` field, or an array/list of numbers) it produces the same
output as `vector.toString()`. An optional format argument selects the layout: `'COMPACT'` (default),
`'PRETTY'`, `'PYTHON'`, `'MATLAB'` (space-separated row), `'MATLAB_COLUMN'` (semicolon-separated column),
`'JULIA'`, or `'NUMPY'` (bare comma-separated for `numpy.fromstring`).
Non-vector values are returned in their natural string form. A non-numeric array is rendered as the list of its
elements (`['a','b']`), exactly like a list. The inverse (string to vector) is `asVector()`.

Syntax: `&lt;value&gt;.asString([&lt;format&gt;])`

Applies to the following types:

- any

*Examples*

Get all the salaries with decimals:

[source,sql]
----
SELECT (salary.asString().indexof('.') > -1) AS hasDecimals FROM Employee
----

Render an embedding vector field in different formats:

[source,sql]
----
SELECT embedding.asString() FROM docs
-- e.g. [0.5, 0.25, 0.75]

SELECT embedding.asString('PYTHON') FROM docs

SELECT embedding.asString('NUMPY') FROM docs
-- e.g. 0.5, 0.25, 0.75   (no brackets, for numpy.fromstring)
----

'''

[[asvector]]
====== asVector()

Parses a value into a vector (`float[]`). This is the inverse of `asString()` for vectors and accepts every
format `asString()` / `vector.toString()` can emit: bracketed or bare, comma-separated
(COMPACT/PYTHON/JULIA/NUMPY), space-separated (MATLAB), semicolon-separated (MATLAB_COLUMN) and multi-line
(PRETTY). It also accepts an array/list of numbers (normalized to `float[]`) and a single number (wrapped
into a one-element vector).

Syntax: `&lt;value&gt;.asVector()`

Applies to the following types:

- string
- array / list of numbers
- number

*Examples*

[source,sql]
----
SELECT '[1.0, 2.0, 3.0]'.asVector()
-- Returns: [1.0, 2.0, 3.0]

SELECT '[1.0 2.0 3.0]'.asVector()
-- Returns: [1.0, 2.0, 3.0]   (MATLAB form)

SELECT '1.0, 2.0, 3.0'.asVector()
-- Returns: [1.0, 2.0, 3.0]   (NUMPY form)

-- Round-trips with asString():
SELECT embedding.asString('MATLAB').asVector() FROM docs
----

'''

----

[[exclude]]
====== exclude()

Answers a map with every property of the value except the excluded ones.

Syntax: `&lt;value&gt;.exclude(&lt;field-name&gt;[,]*)`

Applies to the following types:

- record (document, vertex or edge)
- map
- result row
- collection of the above (each element is projected, and the answer is a list of maps)

The answer is always a map, never a record. It carries no `@rid`, `@type` or `@cat` unless one of the names is a
metadata field: `exclude('@cat', 'secret')` answers `@rid`, `@type` (and `@in`/`@out` on an edge) together with the
properties. Because the answer is a value, `UPDATE ... SET copy = @this.exclude('secret')` stores it as an embedded map,
and a chained access such as `@this.exclude('secret').name` reads the map. A graph traversal like `.out()` needs the
record, so call it before projecting: `out().exclude('secret')`, not `exclude('secret').out()`.

_(Since v26.10.2.)_ In v26.10.1 and earlier the answer was a record copy carrying the source RID (or a map when a
metadata name was given), `UPDATE ... SET x = @this.exclude(..)` stored a link back to the record, and an edge raised
`Cannot copy an edge`.

*Examples*

[source,sql]
----
SELECT expand( @this.exclude( 'password' ) ) FROM User
----

You can specify a wildcard as ending character to exclude all the fields that start with a certain string.
Example to exclude all the outgoing and incoming edges:

[source,sql]
----
SELECT expand( @this.exclude( 'out_*', 'in_*' ) ) FROM V
----

This function can be used to remove internal properties like `@rid`, `@type`, etc.

[source,sql]
----
SELECT @this.exclude('@*') FROM doc
----

On a row of a query (a sub-query result, for example) `exclude()` and `include()` read the row, not the record behind it:
a column the projection overrode answers its projected value, and one it excluded (`!@rid` included) stays out. Before
v26.10.2 they read the record, so `(SELECT *, !m FROM D1)[0].include('m')` answered the stored `m`.

'''

[[normalize]]
====== normalize()

Unicode normalization form can be NDF, NFD, NFKC, NFKD, the default is NDF.
Pattern-matching, if not defined is the regular expression `"\p{InCombiningDiacriticalMarks}+"`.
For more information look at http://www.unicode.org/reports/tr15/tr15-23.html[Unicode Standard].

Syntax: `&lt;value&gt;.normalize( [&lt;form&gt;] [,&lt;pattern-matching&gt;] )`

Applies to the following types:

- string

*Examples*

[source,sql]
----
SELECT FROM V WHERE name.normalize() AND name.normalize('NFD')
----

[[replace]]
====== replace()

Replace a string with another one.
If the value is `null`, or either argument is `null`, `null` is returned, as SQL's `REPLACE()` does.

Syntax: `&lt;value&gt;.replace(&lt;to-find&gt;, &lt;to-replace&gt;)`

Applies to the following types:

- string

*Examples*

[source,sql]
----
SELECT name.replace('Mr.', 'Ms.') FROM User
----

[NOTE]
====
This behavior changed in 26.11.1 (issue #10193). Before, `replace()` on a `null` value returned its first argument (`<to-find>`), so `name.replace('Mr.', 'Ms.')` answered `'Mr.'` for a record without a `name`.
====

[NOTE]
====
_(Since v26.11.1, issue #10485)_ A character outside the Basic Multilingual Plane, such as an emoji, is never cut. With an empty `<to-find>` the replacement goes before every character and after the last, so `'a😀'.replace('', '-')` is `'-a-😀-'`, where it used to put a replacement between the two halves of the emoji. An occurrence is never found inside a character either. `replace()` of the SQL method, the `replace()` function of openCypher and `text.replace()` share one implementation.
====

[[split]]
====== split()

Returns a list from a string separated by the provided delimiter. The delimiter is matched literally, not as a
regular expression. The result is a list, so every collection method can be chained on it:
`'a,b'.split(',').join('-')`, `.sort()`, `.first()`, `.last()`, `.size()`.

Syntax: `&lt;value&gt;.split(&lt;string&gt;)`

Applies to the following types:

- string

*Examples*

Returns string of comma separated values as list

[source,sql]
----
SELECT 'a,b,c,d,e'.split(',')
----

[NOTE]
====
_(Since v26.11.1, issue #10485)_ The empty pieces are kept, as openCypher `split()` keeps them: `'a,'.split(',')` is `['a', '']` and `','.split(',')` is `['', '']`. Before, the empty pieces at the end of the list were dropped (`['a']` and `[]`). An empty delimiter splits a string into its characters, and a character outside the Basic Multilingual Plane, such as an emoji, is one character: `'a😀'.split('')` is `['a', '😀']`, where it used to be `['a', '\uD83D', '\uDE00']`, the two halves of the emoji. The `split()` method and function and `text.split()` of SQL and the `split()` function of openCypher share one implementation, so they answer alike.
====

[[values]]
====== values()

Returns the map's values as a separate collection.
Useful to use in conjunction with IN, CONTAINS and CONTAINSALL operators.

Syntax: `&lt;value&gt;.values()`

Applies to the following types:

- maps
- documents
- query result rows (a sub-query row, a `LET` variable)

`keys()` and `values()` are an index-aligned pair: the n-th value belongs to the n-th key. For a document or a result row
the values are those of the properties `keys()` lists, without the record metadata (`@cat`, `@type`, `@rid`, and `@in` and
`@out` of an edge). A row that overrides a property of its record answers the row's value in that position (_since v26.10.2_;
before, a result row also returned the metadata and the record's value).

*Examples*

[source,sql]
----
SELECT FROM Clients WHERE attributes.values() CONTAINSALL (@this IS NOT NULL)
----

NOTE: A property named like a function namespace (`map`, `geo`, `math`, ...) must be back-ticked to be read as a property: `+`map`.values()+`. Unquoted, `map.values()` calls the `map.*` function.

'''
