==== Utility Functions


[[util-compress]]
===== util.compress()

Compress data using gzip or deflate.

*Syntax:* `util.compress(data, [algorithm])`

*Parameters:*
[%header,cols="2,2,4"]
|===
| Parameter | Type | Description
| data | String | String data to compress
| algorithm | String | Optional - "gzip" (default) or "deflate"
|===

*Returns:* String - Base64-encoded compressed data

NOTE: The input is limited to 10MB. A larger value is rejected with `Input size exceeds maximum allowed`, so that a
single query cannot exhaust server memory.

*APOC Compatible:* `apoc.util.compress`

'''

[[util-decompress]]
===== util.decompress()

Decompress base64-encoded compressed data.

*Syntax:* `util.decompress(data, [algorithm])`

*Returns:* String - Decompressed string

NOTE: The decompressed result is limited to 100MB. Anything larger is rejected with `Decompressed output size exceeds
maximum allowed`, which protects the server against a "zip bomb": a small payload that expands to an enormous one.

*APOC Compatible:* `apoc.util.decompress`

[source,cypher]
----
WITH util.compress("Hello World!") AS compressed
RETURN util.decompress(compressed) AS original
// Returns: "Hello World!"
----

'''

[[util-validate]]
===== util.validate()

Abort the query with an error when a condition holds, as APOC's `apoc.util.validate` does: the predicate states the
condition that must NOT be true. When `params` is a non-empty list, its values fill the `%s` placeholders of the message
(Java `String.format`); without it the message is used as written.

*Syntax:* `util.validate(predicate, message [, params])`

*Returns:* Boolean - true when the predicate is false (or null)

*APOC Compatible:* `apoc.util.validate` (also callable with `CALL`)

[source,cypher]
----
CALL apoc.util.validate(false, 'bad %s', ['x']) RETURN 1 AS ok
// Returns: one row, ok = 1

CALL apoc.util.validate(true, 'bad %s', ['x']) RETURN 1 AS ok
// Throws an error with message "bad x"

// The usual guard: abort the write when the account cannot pay
MATCH (a:Account {id: $id})
CALL apoc.util.validate(a.balance < $amount, 'insufficient balance on %s', [$id])
SET a.balance = a.balance - $amount
----

[NOTE]
====
Up to 26.10.2 `util.validate` took two arguments and threw when the predicate was *false*, the opposite of APOC. It now
follows APOC: it throws when the predicate is *true*. A query written for the old behavior must negate its predicate
(`util.validate(NOT (x > 0), ...)`).
====

---

[[util-validatePredicate]]
===== util.validatePredicate()

The function form of `util.validate()`, usable in a `WHERE` or a `RETURN`: throws when the predicate is true, returns
true otherwise.

*Syntax:* `util.validatePredicate(predicate, message [, params])`

*Returns:* Boolean - true when the predicate is false (or null)

*APOC Compatible:* `apoc.util.validatePredicate`

[source,cypher]
----
MATCH (n:Person)
WHERE apoc.util.validatePredicate(n.age IS NULL, 'person %s has no age', [n.name])
RETURN n.name
----
